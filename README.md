# 圈界 LoopRun

真实跑步闭环产生 50 米六边形领地，服务器计算占领、加固、削弱和匹配。

当前客户端仅交付 **Android App**：React Native / TypeScript / Expo、高德 Android SDK 原生地图、Android 前台定位服务、本机 SQLite。服务端使用 Fastify、PostgreSQL / PostGIS，并复用现有地理计算与游戏规则。

## Android 用户体验

开发者模式默认关闭。普通模式提供真实 GPS 跑步、我的领地、同池争夺、跑友排名与私有跑步记录；途中断网保存在本机，联网后分批上传、幂等结算。

两种模式都以普通用户视角展示首页、真实 GPS「开始跑步」、位置分享、领地、同池跑友和私有记录。开启首页上方抽屉中的开发者开关后，切换至独立开发测试账户与数据库，在「开始跑步」同一行增加「虚拟跑步」，并显示「机器人设置」。虚拟跑步可选择预设闭环加速完成；机器人设置选择道路路线和 0–99% 起跑位置（含 0/25/50/75% 预设），可启动一位或 5 位预设用户。模拟跑步约 14 秒播放完成，再通过正常采样与结算接口提交。机器人使用相同用户类型、鉴权、普通 GPS 与共享位置接口，按真实时间逐步采样，不预置领地、不强制入池、不直接修改数据库。地图按正常附近位置接口显示它们。

首页以上下可收起抽屉让出地图空间；上方展开领地、跑友、记录、设置与开发开关，下方展开跑步选项。默认保留跑步主按钮，运动时保留距离、时间和结束按钮。抽屉支持把手点击与上下拖动，最多展开一个。地图支持平移与缩放；只绘制已有归属的领地，中立区域不绘制网格边线或底色。地图不再提供悬浮隐私政策按钮，首次使用说明仍保留政策入口。地图人物默认不显示名字，点击选中后显示名字，再点同一人物或名字打开公开详情；点击地图空白处取消选中。同池详情展示公开领地，非同池保持匿名，不公开原始轨迹。

两套服务器连接和凭据分别保存在本机 Keystore 保护的配置中。切换前必须处理本机与服务器未完成活动；关闭后恢复普通账户视角，隐藏测试工具与测试记录。

## 本机启动

需要 Node.js 24+、PostgreSQL 18 / PostGIS、Android SDK 和 JDK。根目录与 apps/mobile/ 分别执行 npm ci。

1. npm run gps:db：准备本机普通 GPS 数据库。
2. npm run gps:dev：启动普通服务，默认 http://127.0.0.1:4180 。
3. npm run developer:db：在同一本机 PostgreSQL 实例内准备独立开发库。
4. npm run developer:dev：启动开发服务，默认 http://127.0.0.1:4182 。
5. 在本地 .local-credentials/amap.json 配置 androidKey（高德 Android SDK Key，绑定包名和签名），或设置 LOOPRUN_AMAP_KEY。
6. npm run android:build：输出 artifacts/LoopRun-0.5.2-android-arm64.apk。

手机通过 USB 连接后，对 4180 和 4182 分别执行 adb reverse。App 设置中填写对应服务地址和各自的内测邀请口令。普通口令位于 .env.gps.local，开发口令位于 .env.development.local，不写入客户端或共享文档。

高德 3D SDK 当前构建仅支持 ARM64 真机；不交付 x86_64 模拟器安装包。

## 项目入口

- apps/mobile/：唯一客户端交付与验收入口。
- server/gps.ts：普通 GPS 与独立开发服务，共用活动、采样及结算接口。
- server/replay-bots.mjs：通过正常 HTTP 接口运行的自动用户。
- shared/：50 米网格与共用地理计算。
